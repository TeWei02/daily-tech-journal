# 管道与命令替换的错误处理：性能与复杂度权衡

**日期**：2026-08-28　**领域**：Linux　**编号**：40/115

## 背景

先量化再优化，凭感觉换实现经常得不偿失。这里围绕「管道与命令替换的错误处理」做一次整理，重点放在能直接落地的部分。

## 要点

- set -o pipefail 让管道中任一环节失败即整体失败
- 命令替换失败不会终止脚本，需要显式判断
- 优化前后都要有可复现的基准数据。

## 示例

```bash
set -euo pipefail
count=$(grep -c FAIL app.log || true)
```

## 易错点

- grep 无匹配返回 1，配合 set -e 会误退出

## 小结

管道与命令替换的错误处理 在性能与复杂度权衡这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
