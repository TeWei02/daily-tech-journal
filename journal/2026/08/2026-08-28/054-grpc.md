# gRPC 流控与超时传递：性能与复杂度权衡

**日期**：2026-08-28　**领域**：网络　**编号**：54/115

## 背景

先量化再优化，凭感觉换实现经常得不偿失。这里围绕「gRPC 流控与超时传递」做一次整理，重点放在能直接落地的部分。

## 要点

- DEADLINE_EXCEEDED 会在跨服务调用链上传播并逐级缩短
- 流控基于 HTTP/2 窗口，慢消费者会反压上游
- 优化前后都要有可复现的基准数据。

## 示例

```bash
ctx, cancel = context.with_timeout(ctx, 2.0)
resp = stub.Query(ctx, req)
```

## 易错点

- 忘记取消会泄漏协程与连接

## 小结

gRPC 流控与超时传递 在性能与复杂度权衡这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
