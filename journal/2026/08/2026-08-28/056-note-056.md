# 索引失效的常见写法：性能与复杂度权衡

**日期**：2026-08-28　**领域**：数据库　**编号**：56/115

## 背景

先量化再优化，凭感觉换实现经常得不偿失。这里围绕「索引失效的常见写法」做一次整理，重点放在能直接落地的部分。

## 要点

- 对列做函数运算、隐式类型转换都会让索引失效
- 前置通配 LIKE '%x' 无法走上索引
- 优化前后都要有可复现的基准数据。

## 示例

```sql
WHERE created_at >= '2026-01-01'      -- 走索引
WHERE date(created_at) = '2026-01-01'  -- 不走索引
```

## 易错点

- 统计信息过期时执行计划可能偏离，需要 analyze

## 小结

索引失效的常见写法 在性能与复杂度权衡这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
