# 读写锁与场景选择：性能与复杂度权衡

**日期**：2026-08-28　**领域**：并发　**编号**：76/115

## 背景

先量化再优化，凭感觉换实现经常得不偿失。这里围绕「读写锁与场景选择」做一次整理，重点放在能直接落地的部分。

## 要点

- 读多写少用读写锁，写竞争激烈时可能不如互斥量
- 写饥饿需要公平模式或写优先策略
- 优化前后都要有可复现的基准数据。

## 示例

```cpp
std::shared_mutex mu;
{ std::shared_lock lk(mu); read(); }
{ std::unique_lock lk(mu); write(); }
```

## 易错点

- 读锁里做长耗时任务会阻塞写者

## 小结

读写锁与场景选择 在性能与复杂度权衡这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
