# SQL 注入与参数化查询：边界条件与异常路径

**日期**：2026-08-29　**领域**：安全　**编号**：61/115

## 背景

空集合、极值、超时、部分失败，这几类最容易漏。这里围绕「SQL 注入与参数化查询」做一次整理，重点放在能直接落地的部分。

## 要点

- 拼接字符串是注入根源，参数化让数据与语句分离
- 表名与列名无法参数化，需要白名单校验
- 边界用例应固化成自动化测试。

## 示例

```python
cur.execute('SELECT * FROM users WHERE email = %s', (email,))
```

## 易错点

- ORM 中的原生 SQL 拼接同样有风险

## 小结

SQL 注入与参数化查询 在边界条件与异常路径这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
