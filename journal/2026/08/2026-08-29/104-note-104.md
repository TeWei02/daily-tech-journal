# 文件描述符与重定向顺序：方案对比与选型

**日期**：2026-08-29　**领域**：Linux　**编号**：104/115

## 背景

把候选方案的代价列清楚，选型就不再靠偏好。这里围绕「文件描述符与重定向顺序」做一次整理，重点放在能直接落地的部分。

## 要点

- 2>&1 的位置决定拷贝的是哪个描述符
- exec 3>&1 可保存现场供后续恢复
- 选型结论要写清前提，否则换个环境就不成立。

## 示例

```bash
cmd >out.log 2>&1
exec 3>&1 1>tmp.log 2>&1
```

## 易错点

- cmd 2>&1 >f 只把 stderr 指向终端

## 小结

文件描述符与重定向顺序 在方案对比与选型这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
