# 表单校验的前后端分工：方案对比与选型

**日期**：2026-08-30　**领域**：Web　**编号**：21/115

## 背景

把候选方案的代价列清楚，选型就不再靠偏好。这里围绕「表单校验的前后端分工」做一次整理，重点放在能直接落地的部分。

## 要点

- 前端校验提升体验，后端校验保证正确性，二者都要有
- 统一错误码便于前端映射提示文案
- 选型结论要写清前提，否则换个环境就不成立。

## 示例

```js
{ "code": "INVALID_EMAIL", "field": "email" }
```

## 易错点

- 只在后端校验会导致用户反复提交

## 小结

表单校验的前后端分工 在方案对比与选型这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
