# 事件委托与动态节点：方案对比与选型

**日期**：2026-08-30　**领域**：Web　**编号**：19/115

## 背景

把候选方案的代价列清楚，选型就不再靠偏好。这里围绕「事件委托与动态节点」做一次整理，重点放在能直接落地的部分。

## 要点

- 在容器上监听可覆盖后续新增节点，减少监听器数量
- 注意事件冒泡被 stopPropagation 截断的情况
- 选型结论要写清前提，否则换个环境就不成立。

## 示例

```js
list.addEventListener('click', e => {
  const row = e.target.closest('[data-id]')
  if (row) open(row.dataset.id)
})
```

## 易错点

- 过度委托到 document 会让排查变困难

## 小结

事件委托与动态节点 在方案对比与选型这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
