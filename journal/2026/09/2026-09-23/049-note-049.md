# 内存与交换区观测：代码评审关注点

**日期**：2026-09-23　**领域**：Linux　**编号**：49/104

## 背景

评审优先看契约与失败路径，其次才是实现技巧。这里围绕「内存与交换区观测」做一次整理，重点放在能直接落地的部分。

## 要点

- buff/cache 可被回收，判断内存压力看 available 而非 free
- si/so 持续非零说明已经在换页
- 把重复出现的意见沉淀成团队约定。

## 示例

```bash
vmstat 1 5
cat /proc/pressure/memory
```

## 易错点

- OOM 记录在 dmesg，容器里常被聚合到事件流

## 小结

内存与交换区观测 在代码评审关注点这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
