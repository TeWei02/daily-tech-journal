# 位运算与位域陷阱：代码评审关注点

**日期**：2026-09-23　**领域**：C/C++　**编号**：39/104

## 背景

评审优先看契约与失败路径，其次才是实现技巧。这里围绕「位运算与位域陷阱」做一次整理，重点放在能直接落地的部分。

## 要点

- 有符号右移是实现定义行为，优先使用无符号
- 位域的内存布局依赖编译器，不适合序列化
- 把重复出现的意见沉淀成团队约定。

## 示例

```cpp
uint32_t mask = (1u << n) - 1;
value = (value >> shift) & mask;
```

## 易错点

- 1<<31 是未定义行为，写 1u<<31

## 小结

位运算与位域陷阱 在代码评审关注点这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
