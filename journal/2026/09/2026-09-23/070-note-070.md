# CI 缓存与构建加速：代码评审关注点

**日期**：2026-09-23　**领域**：工程　**编号**：70/104

## 背景

评审优先看契约与失败路径，其次才是实现技巧。这里围绕「CI 缓存与构建加速」做一次整理，重点放在能直接落地的部分。

## 要点

- 缓存键要包含依赖清单哈希，否则会出现幽灵构建
- 缓存目录分层，把变动频繁的放上层
- 把重复出现的意见沉淀成团队约定。

## 示例

```bash
- uses: actions/cache@v4
  with:
    key: deps-${{ hashFiles('**/requirements.txt') }}
```

## 易错点

- 缓存工具本身出错时会导致构建不稳定

## 小结

CI 缓存与构建加速 在代码评审关注点这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
