**日期**：2026-09-10　**领域**：Linux　**编号**：63/99

## 背景

多数线上问题不是不会用，而是用错了一个细节。这里围绕「文本处理的性能差异」做一次整理，重点放在能直接落地的部分。

## 要点

- awk 单遍扫描适合列提取，sed 适合流式替换
- 大文件优先用 LC_ALL=C 提升字符处理速度
- 把踩过的坑写成检查项，比背结论更有效。

## 示例

```bash
LC_ALL=C awk -F, '$3 > 100 { n++ } END { print n }' big.csv
```

## 易错点

- 默认 locale 下多字节处理会显著变慢

## 小结

文本处理的性能差异 在常见陷阱与错误示范这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
