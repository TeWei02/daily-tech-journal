# TCP 三次握手与半连接队列：配置与参数调优

**日期**：2026-09-18　**领域**：网络　**编号**：83/115

## 背景

参数调整必须一次只改一个，否则无法归因。这里围绕「TCP 三次握手与半连接队列」做一次整理，重点放在能直接落地的部分。

## 要点

- SYN 队列与 accept 队列分离，溢出时按 tcp_abort_on_overflow 决定行为
- syncookies 可在半连接溢出时继续服务但牺牲部分选项
- 调优结论要绑定当时的负载特征。

## 示例

```bash
ss -lnt
# Recv-Q 为当前 accept 队列长度，Send-Q 为 backlog 上限
```

## 易错点

- backlog 调大不等于能扛住 SYN Flood，需要内核参数配合

## 小结

TCP 三次握手与半连接队列 在配置与参数调优这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
