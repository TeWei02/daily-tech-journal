# 条件变量与虚假唤醒：测试与验证策略

**日期**：2026-09-16　**领域**：C/C++　**编号**：27/115

## 背景

测试要覆盖正常、边界与失败三类路径。这里围绕「条件变量与虚假唤醒」做一次整理，重点放在能直接落地的部分。

## 要点

- wait 必须配谓词，否则会被虚假唤醒打穿
- 通知前先改状态并加锁，避免丢信号
- 测试用例本身也要可维护。

## 示例

```cpp
std::unique_lock lk(m);
cv.wait(lk, [&]{ return !queue.empty(); });
auto job = std::move(queue.front()); queue.pop_front();
```

## 易错点

- notify 时若未持锁可能导致等待者错过判断

## 小结

条件变量与虚假唤醒 在测试与验证策略这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
