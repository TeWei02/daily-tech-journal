## 背景

先把行为固定住再改结构，避免同时改两件事。这里围绕「RAII 与资源释放顺序」做一次整理，重点放在能直接落地的部分。

## 要点

- 析构按构造逆序执行，成员按声明顺序构造、逆序析构
- 异常路径同样会析构，这正是 RAII 的价值
- 重构后接口不变，调用方无感。

## 示例

```cpp
struct File {
    FILE* f;
    File(const char* p) : f(fopen(p, "r")) {}
    ~File() { if (f) fclose(f); }
};
```

## 易错点

- 成员初始化列表顺序应与声明一致，否则警告

## 小结

RAII 与资源释放顺序 在重构与可维护性这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
