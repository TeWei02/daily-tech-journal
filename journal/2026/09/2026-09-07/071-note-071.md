# Git 提交粒度与可回溯性：代码评审关注点

**日期**：2026-09-07　**领域**：工程　**编号**：71/115

## 背景

评审优先看契约与失败路径，其次才是实现技巧。这里围绕「Git 提交粒度与可回溯性」做一次整理，重点放在能直接落地的部分。

## 要点

- 一个提交只做一件事，便于 revert 与 bisect
- 提交信息写清动机而非仅描述改动
- 把重复出现的意见沉淀成团队约定。

## 示例

```bash
git commit -m "fix(cache): 修正过期判断，避免负 TTL 被当作永不过期"
```

## 易错点

- 混合提交会让回滚牵连无关代码

## 小结

Git 提交粒度与可回溯性 在代码评审关注点这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
