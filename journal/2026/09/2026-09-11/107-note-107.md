# 可观测性三支柱关联：性能与复杂度权衡

**日期**：2026-09-11　**领域**：工具　**编号**：107/115

## 背景

先量化再优化，凭感觉换实现经常得不偿失。这里围绕「可观测性三支柱关联」做一次整理，重点放在能直接落地的部分。

## 要点

- 用 trace id 把日志、指标、链路串起来
- 指标看趋势，链路看个案，日志看细节
- 优化前后都要有可复现的基准数据。

## 示例

```yaml
log.info('order ok', extra={'trace': trace_id})
```

## 易错点

- 缺少 trace 关联会让排障退化为翻日志

## 小结

可观测性三支柱关联 在性能与复杂度权衡这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
