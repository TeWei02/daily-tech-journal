# 日志结构化与检索成本：常见陷阱与错误示范

**日期**：2026-09-11　**领域**：工具　**编号**：17/115

## 背景

多数线上问题不是不会用，而是用错了一个细节。这里围绕「日志结构化与检索成本」做一次整理，重点放在能直接落地的部分。

## 要点

- 统一 JSON 字段名，避免同义字段导致检索遗漏
- 高基数字段不要索引，成本会失控
- 把踩过的坑写成检查项，比背结论更有效。

## 示例

```yaml
{"ts":"2026-09-14T08:00:00Z","lvl":"error","svc":"api","trace":"7f3a"}
```

## 易错点

- 把完整请求体写进日志会带来合规与容量问题

## 小结

日志结构化与检索成本 在常见陷阱与错误示范这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
