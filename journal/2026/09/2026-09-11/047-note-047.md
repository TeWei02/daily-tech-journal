# 条件变量与虚假唤醒：性能与复杂度权衡

**日期**：2026-09-11　**领域**：C/C++　**编号**：47/115

## 背景

先量化再优化，凭感觉换实现经常得不偿失。这里围绕「条件变量与虚假唤醒」做一次整理，重点放在能直接落地的部分。

## 要点

- wait 必须配谓词，否则会被虚假唤醒打穿
- 通知前先改状态并加锁，避免丢信号
- 优化前后都要有可复现的基准数据。

## 示例

```cpp
std::unique_lock lk(m);
cv.wait(lk, [&]{ return !queue.empty(); });
auto job = std::move(queue.front()); queue.pop_front();
```

## 易错点

- notify 时若未持锁可能导致等待者错过判断

## 小结

条件变量与虚假唤醒 在性能与复杂度权衡这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
