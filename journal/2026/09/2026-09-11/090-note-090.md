# 熔断器状态机：性能与复杂度权衡

**日期**：2026-09-11　**领域**：系统　**编号**：90/115

## 背景

先量化再优化，凭感觉换实现经常得不偿失。这里围绕「熔断器状态机」做一次整理，重点放在能直接落地的部分。

## 要点

- 关闭、打开、半开三态，半开只放少量探测流量
- 基于滑动窗口的失败率比连续失败计数更稳
- 优化前后都要有可复现的基准数据。

## 示例

```python
if breaker.is_open():
    return fallback()
```

## 易错点

- 熔断恢复过快会导致反复抖动

## 小结

熔断器状态机 在性能与复杂度权衡这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
