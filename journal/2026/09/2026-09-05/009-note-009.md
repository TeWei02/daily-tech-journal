# 条件变量与虚假唤醒：与相邻技术的配合

**日期**：2026-09-05　**领域**：C/C++　**编号**：9/115

## 背景

它很少单独出现，和上下游的约定决定了整体效果。这里围绕「条件变量与虚假唤醒」做一次整理，重点放在能直接落地的部分。

## 要点

- wait 必须配谓词，否则会被虚假唤醒打穿
- 通知前先改状态并加锁，避免丢信号
- 跨组件问题先在边界处抓包或打日志。

## 示例

```cpp
std::unique_lock lk(m);
cv.wait(lk, [&]{ return !queue.empty(); });
auto job = std::move(queue.front()); queue.pop_front();
```

## 易错点

- notify 时若未持锁可能导致等待者错过判断

## 小结

条件变量与虚假唤醒 在与相邻技术的配合这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
