# 文本处理的性能差异：代价与适用边界

**日期**：2026-09-05　**领域**：Linux　**编号**：104/115

## 背景

任何方案都有不适用的时候，提前写清楚。这里围绕「文本处理的性能差异」做一次整理，重点放在能直接落地的部分。

## 要点

- awk 单遍扫描适合列提取，sed 适合流式替换
- 大文件优先用 LC_ALL=C 提升字符处理速度
- 把不适用条件写进文档，避免误用。

## 示例

```bash
LC_ALL=C awk -F, '$3 > 100 { n++ } END { print n }' big.csv
```

## 易错点

- 默认 locale 下多字节处理会显著变慢

## 小结

文本处理的性能差异 在代价与适用边界这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
