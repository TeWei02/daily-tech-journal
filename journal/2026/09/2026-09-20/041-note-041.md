# 慢查询定位流程：代价与适用边界

**日期**：2026-09-20　**领域**：数据库　**编号**：41/54

## 背景

任何方案都有不适用的时候，提前写清楚。这里围绕「慢查询定位流程」做一次整理，重点放在能直接落地的部分。

## 要点

- 先看 slow log 与执行计划，再判断是索引问题还是回表过多
- 覆盖索引可消除回表，但会增加索引体积
- 把不适用条件写进文档，避免误用。

## 示例

```sql
EXPLAIN ANALYZE SELECT id, name FROM t WHERE code = 'x';
```

## 易错点

- 只看 EXPLAIN 不够，实际行数与估算差异大时要 analyze

## 小结

慢查询定位流程 在代价与适用边界这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
