# 文件描述符与重定向顺序：测试与验证策略

**日期**：2026-09-01　**领域**：Linux　**编号**：115/115

## 背景

测试要覆盖正常、边界与失败三类路径。这里围绕「文件描述符与重定向顺序」做一次整理，重点放在能直接落地的部分。

## 要点

- 2>&1 的位置决定拷贝的是哪个描述符
- exec 3>&1 可保存现场供后续恢复
- 测试用例本身也要可维护。

## 示例

```bash
cmd >out.log 2>&1
exec 3>&1 1>tmp.log 2>&1
```

## 易错点

- cmd 2>&1 >f 只把 stderr 指向终端

## 小结

文件描述符与重定向顺序 在测试与验证策略这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
