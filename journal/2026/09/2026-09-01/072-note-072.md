# SQL 注入与参数化查询：并发与线程安全

**日期**：2026-09-01　**领域**：安全　**编号**：72/115

## 背景

共享可变状态是并发问题的根源，能消除就消除。这里围绕「SQL 注入与参数化查询」做一次整理，重点放在能直接落地的部分。

## 要点

- 拼接字符串是注入根源，参数化让数据与语句分离
- 表名与列名无法参数化，需要白名单校验
- 并发缺陷难以复现，需靠压测与竞态注入暴露。

## 示例

```python
cur.execute('SELECT * FROM users WHERE email = %s', (email,))
```

## 易错点

- ORM 中的原生 SQL 拼接同样有风险

## 小结

SQL 注入与参数化查询 在并发与线程安全这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
