# 位运算与位域陷阱：方案对比与选型

**日期**：2026-09-12　**领域**：C/C++　**编号**：107/115

## 背景

把候选方案的代价列清楚，选型就不再靠偏好。这里围绕「位运算与位域陷阱」做一次整理，重点放在能直接落地的部分。

## 要点

- 有符号右移是实现定义行为，优先使用无符号
- 位域的内存布局依赖编译器，不适合序列化
- 选型结论要写清前提，否则换个环境就不成立。

## 示例

```cpp
uint32_t mask = (1u << n) - 1;
value = (value >> shift) & mask;
```

## 易错点

- 1<<31 是未定义行为，写 1u<<31

## 小结

位运算与位域陷阱 在方案对比与选型这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
