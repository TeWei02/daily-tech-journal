# 容器镜像瘦身：代价与适用边界

**日期**：2026-09-22　**领域**：工具　**编号**：25/104

## 背景

任何方案都有不适用的时候，提前写清楚。这里围绕「容器镜像瘦身」做一次整理，重点放在能直接落地的部分。

## 要点

- 多阶段构建把编译工具留在中间层
- 注意层缓存顺序，把变动少的指令前置
- 把不适用条件写进文档，避免误用。

## 示例

```yaml
FROM golang:1.22 AS build
RUN go build -o /app .
FROM gcr.io/distroless/base
COPY --from=build /app /app
```

## 易错点

- 把 .git 与测试数据打进镜像会显著增大体积

## 小结

容器镜像瘦身 在代价与适用边界这一面，结论可以归纳为：把前提写清楚、把失败路径覆盖到，剩下的就是按数据调优。
